# 已知问题

这些是 v1.0 明确不解决、但不会阻塞发布的问题。遇到时按“规避”处理；需要完整背景可看[开发文档](dev/README.md)里的历史资料。

## 1. 游戏内全屏异常

**现象**：部分老游戏切游戏内全屏时，X11 路径黑屏；Wayland 路径画面居左、点击错位。KDE 直连该游戏时也可能异常。

**原因**：X11 全屏画面画在 override-redirect 窗口上，按 toplevel 抓取看不到；Wayland 游戏看到的屏幕几何与实际 surface 不一致。

**规避**：让游戏保持窗口化/无边框窗口，用嵌套模式超分。不要用游戏自己的独占全屏。

## 2. 原生 Wayland 窗口化输入

已有原生 Wayland 窗口模式只支持全屏 + 输入穿透。窗口化的原生 Wayland 游戏请用嵌套启动；该路径会转发输入。

## 3. 自我最小化

- X11 游戏按 Esc 自我最小化时，宿主窗口不会跟着最小化；从任务栏恢复游戏即可。
- 原生 Wayland 的 `set_minimized` 没有取消请求；游戏自我最小化后，需要用户从任务栏恢复宿主窗口。

## 4. 游戏自定义光标

只转发命名光标形状（`wp_cursor_shape_v1`）。用图像光标（`wl_pointer.set_cursor`）的游戏，按钮上的“手”等自定义光标仍显示默认箭头。不影响点击。

## 5. FPS / 鼠标视角 / raw input

XWayland 的指针锁、relative、raw input 没有实现；原生 Wayland 嵌套有 relative，但 v1.0 不承诺 FPS/3D 游戏。请只用视觉小说/2D 场景验收。

## 6. HDR 与色彩

- HDR 桌面下 SDR 直通正常，但不做 HDR 游戏捕获、10-bit 输出或 HDR 色彩管理。
- 不做完整的 SDR 色彩准确性回归；极端情况下可能与桌面直连有轻微色彩差异。

## 7. 4K 源

v1.0 只承诺常见 720p/1024×768/1080p 源。4K 源做 2× 会得到 8K，显存和带宽开销很大，未验收。

## 8. 多显示器

- 不做跨屏连续拼接，每块屏独立输出。
- 运行中的嵌套会话不跟随显示器热插拔/分辨率/刷新率变化；重新开始会话后生效。
- 多屏焦点跟随可能在操作另一块屏时收起覆盖层，这是预期行为。

## 9. 原生 Wayland 捕获的边界

- portal/PipeWire 路径按 KDE 输出 scale 合成；低分辨率全屏源在 4K 屏上可能得到 4K 流，2× 没有真实收益。此类场景请用嵌套或 X11/XWayland 捕获。
- 捕获可能包含标题栏/阴影；正式使用以全屏/无边框为准。

## 10. 性能与呈现

- 嵌套 toplevel 抓帧默认走 shm；4K 源的 capture 可能成为瓶颈（约 24 fps），720p/800p 视觉小说不受影响。DMA-BUF 零拷贝是 v1.0 后可选优化。
- 非嵌套 X11/XWayland 的 GPU 窗口可能撕裂；v1.0 主路径（嵌套 + toplevel）不走该路径。
- 不做进出超分动画。

## 11. 其他

- 第二个 CLI 实例始终返回退出码 4；GUI 的“激活已有窗口”只在 GUI 场景生效。
- 托盘不可用时不能“最小化到托盘”，会自动回退为直接退出。
- 热键固定 `Alt+Shift+A`，v1.0 不支持修改。
- 自定义 effect 只支持 compute pass + 内置 Lanczos-2 收尾；纹理上限 19、单 pass 输入 16、push constant 上限 256 B（设备可能更低）。
- 不提供 Flatpak、AUR、系统安装脚本或 `.desktop` 文件。

v1.0 之后可能处理的方向见[开发计划](dev/post-v1.0.md)。
